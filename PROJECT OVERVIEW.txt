PROJECT OVERVIEW

The website is a Pokémon Team Builder Platform focused on team building, team analysis, strategy presets, and team visualization.

This project is NOT intended to be a full Pokédex encyclopedia website like https://pokemondb.net.

The Pokédex exists mainly to support the Team Builder experience.

The core of the website is:
- Manual Team Builder
- Team Coverage Analysis
- Team Checklist Analysis
- Recommendation Engine
- Preset Strategy Teams
- Team Card Generator

The website takes inspiration from:
- https://mypokemonteam.com (Team Builder and team analysis)
- https://pokemondb.net (Pokédex UI structure and Pokémon browsing)

However, this project should have its own cleaner modern UI/UX and should not clone either website directly.

VI. TEAM BUILDER
--------------------------------------------------

This is the most important feature of the website.

The Team Builder must support:
- Singles
- Doubles
- Triples

Users can create a team of up to 6 Pokémon.

Each Pokémon slot must contain:

- Pokémon name
- 2D normal sprite
- Ability dropdown
- Item dropdown
- Move 1 dropdown
- Move 2 dropdown
- Move 3 dropdown
- Move 4 dropdown
- Remove button
- Replace button

IMPORTANT:
For the MVP:
- Team Builder uses ONLY 2D normal sprites
- No 3D animated models
- No animated motion sprites

Reason:
- better performance
- lighter assets
- easier implementation
- faster loading

Move dropdown behavior:
Search should be keyword-based.

Example:
Searching:
"flame"

Should return:
- Flamethrower
- Flame Charge
- Flame Wheel

Should NOT return:
- Will-O-Wisp

The move search should behave like:
"name contains keyword"

NOT semantic search.

--------------------------------------------------
VII. COVERAGE ANALYSIS
--------------------------------------------------

Coverage analysis must update in real-time whenever:
- Pokémon changes
- Ability changes
- Item changes
- Move changes

There are TWO major analysis systems:

A. DEFENSIVE COVERAGE

The system should calculate:
- weaknesses
- resistances
- immunities

For all Pokémon types.

Example:
Fire:
- Weak: 2
- Resist: 3
- Immune: 0

Ground:
- Weak: 3
- Resist: 1
- Immune: 1

The UI should visually indicate:
- weaknesses in red
- resistances in green
- neutral in gray

B. OFFENSIVE TYPE COVERAGE

This must be based on actual MOVES selected.

NOT based only on Pokémon types.

Example:
If the team has:
- Thunderbolt
- Wild Charge

Then the team has Electric offensive coverage.

If moves are missing:
- offensive coverage may be incomplete

This system should analyze:
- which types the team can hit effectively
- missing offensive coverage

--------------------------------------------------
IX. RECOMMENDATION ENGINE
--------------------------------------------------

The recommendation engine is NOT AI-based.

It is fully rule-based and score-based.

The recommendation system should analyze:
- team weaknesses
- offensive gaps
- defensive gaps
- missing roles
- format compatibility
- type synergy
- ability synergy
- stat tiers

The recommendation engine should support filters:

- No legendary / mythical
- All regions
- Generation (I, II, III, IV, V, VI, VII, VIII, IX)
- Type
- Role
- Format (Singles / Doubles / Triples)
- Attack tier
- Defense tier
- Sp. Atk tier
- Sp. Def tier
- Speed tier

IMPORTANT:
Legendary and mythical Pokémon are treated as ONE combined category for simplicity.

Stat tier examples:
- Low
- Medium
- High
- Very High

The recommendation engine should score Pokémon using logic such as:

score =
+ defensive synergy
+ offensive synergy
+ missing role bonus
+ format compatibility
+ ability synergy
+ stat tier compatibility
- duplicate weaknesses
- duplicate roles
- duplicate typings

The engine should return:
- Top 5–10 recommendations

Each recommendation should include:
- Pokémon
- short explanation

Example:
"Rotom-Wash is recommended because it improves Ground immunity, adds Electric coverage, and supports defensive balance."

No AI-generated text should be used.

XIII. TEAM CARD GENERATOR
--------------------------------------------------

The Team Card Generator creates visual shareable Pokémon team cards.

NO custom uploads are supported in the MVP.

The system should use ONLY prepared assets.

Prepared assets include:
- preset backgrounds
- preset trainer images
- Pokémon sprites

The Team Card Generator should support:
- normal sprites
- shiny sprites

IMPORTANT:
The Team Builder uses only normal sprites.

However:
The Team Card Generator allows:
- normal
- shiny

for visual customization.

The generated card should include:
- team name
- trainer image
- background
- 6 Pokémon sprites
- format label
- optional type icons

The card should export as PNG.
